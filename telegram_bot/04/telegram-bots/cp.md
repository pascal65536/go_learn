#### 1. **Callback API**
- Приходит запрос на роут вида:
  ```
  POST https://mysite.com/bot/<name_bot>
  ```
- Это позволяет сразу понять, **какой бот должен обработать это событие**

---

#### 2. **Идентификация бота**
- `name_bot` из URL используется как ключ для поиска конфигурации
- Конфиг хранится в структурированном виде (например, JSON или YAML)
- Из конфига берём:
  - `token_bot` – токен для Telegram API
  - `class_bot` – тип бота, определяющий его поведение
  - дополнительные параметры, специфичные для этого экземпляра

---

#### 3. **Класс бота (`class_bot`)**
- Это не просто набор функций — это **логическая единица поведения**
- Например:
  - `CatBot` – отвечает мурлычущими сообщениями
  - `DogBot` – лает и просит еду
  - `AdminBot` – управляет другими ботами
- Каждый класс реализует один и тот же интерфейс:
  ```go
  type BotClass interface {
    HandleMessage(text string)
    HandleCommand(cmd string)
    // и т.д.
  }
  ```

---

#### 4. **Загрузка настроек**
- Настройки всех ботов хранятся в одном файле (например, `bots.yaml` или `bots.json`)
- Пример содержания:
  ```yaml
  bots:
    bot_cat:
      token: "token123"
      class: "CatBot"
      settings:
        greeting: "Мяу! Я рад тебя видеть!"
        favorite_food: "Рыбка"

    bot_dog:
      token: "token456"
      class: "DogBot"
      settings:
        greeting: "Гав! Давай гулять!"
        favorite_toy: "Мячик"
  ```

- При старте программы или при первом вызове конкретного бота — загружается его конфиг

---

### 🔁 Как всё работает вместе:

1. Приходит запрос на `/bot/bot_cat`
2. Извлекаем `name_bot = bot_cat`
3. Ищем в конфиге запись с таким именем
4. Загружаем:
   - `token_bot`
   - `class_bot` (например, `CatBot`)
   - `settings` (специфичные для этого бота)
5. Создаём объект бота нужного типа
6. Вызываем у него нужный метод:
   - например, `HandleMessage("Привет")`
7. Если метод не реализован — вызывается дефолтный обработчик из главной программы
8. Метод использует данные из `settings`, чтобы адаптировать ответ
